## Isolated loopback HTTP candidate (not integrated)

`service.py` now admits exactly one configured channel and serves a local-only version of `/api/live/:id/authorize`, `/index.m3u8`, and signed `/segment/:n.ts`. `authorize` requires an explicit bearer API key, and the playlist/each segment gets its own HMAC-bound, expiring URL. It consumes bounded HTTP chunked or length-delimited TS responses through PyAV, reopens after EOF and a bounded idle-read stall, feeds one retained `Stitcher` and one persistent FFmpeg HLS child. A wrong length, unsupported media, absent/ambiguous or shifted overlap, resource cap, or cancellation seals the service and clears its manifest rather than playing raw replay. This is **not** the application signing/authentication code or its production live route; it accepts only an explicit HTTP URL and listens exclusively on 127.0.0.1. Never expose it outside loopback or use actual provider credentials in a command line.

Run the demo with a private, empty output directory and a controlled local TS source; supply `LIVE_DEMO_SOURCE_URL` and `LIVE_DEMO_API_KEY` in the environment, then run `/usr/bin/python3 prototypes/live_packet_continuity/service.py --directory <private-empty-dir>`. It prints the local port but no source URL or ticket. Query `/api/live/demo/authorize` with `Authorization: Bearer <your-key>` and resolve the returned `playlistUrl` against the loopback origin; each manifest segment URL is independently signed. The finite demonstration stops ingest at eight sessions or 180 seconds by default but keeps HTTP serving until Ctrl-C. Ctrl-C deletes the disposable HLS files. Do not point this demo at a production provider or expose its ticket URL in logs. The deterministic mock-source test is the recommended way to exercise it without secrets:

```
/usr/bin/python3 -m unittest discover -s prototypes/live_packet_continuity -v
```

The local end-to-end test reopens at a real chunked EOF into a Content-Length EOF, checks unauthorized/tampered tickets, fetches signed segments, and verifies the captured unique non-IDR packet and strict decode across the seam. Separate tests cover a silent chunked stall, a lying Content-Length, cancellation and disk-cap cleanup. The existing synthetic and captured media gates cover ambiguous/static, shifted AAC and missing packets. The service is a bounded trial, not a production fallback: any unsafe seam returns unavailable; it never enables raw replay. The captured fixture's *final* packet remains truncated and is excluded from full-tail strict-decode claims.

A disposable packaging proof is `docker build --network=host -f prototypes/live_packet_continuity/Dockerfile.proof -t streamvault-packet-proof:local prototypes/live_packet_continuity`; it installs Debian's `/usr/bin/python3` + `python3-av` alongside FFmpeg, not the separate `/usr/local/bin/python3` in the base image. Run `/usr/bin/python3 -c 'import av; print(av.__version__)'` inside the image to verify the correct interpreter. The disposable arm64 image **built successfully** (`sha256:8cd9c224b2bce5103be34004463355d5154ba4291b9fc350b38792c0668f1e52`), and a separate `docker run` imported `av`, `service`, and `stitch` with PyAV 14.2.0. This image is not used in Compose; its successful import does not imply deployment readiness.

**Outstanding blockers:** no integration with StreamVault auth/channel admission or its live route; no production quota/free-space reserve, per-channel coalescing, viewer pinning, startup recovery, retirement or multi-channel load budget. The scanner counts files periodically and has no strict synchronous disk limit between polls. Socket timeout is per blocking read, not a guarantee of real-time catch-up; transport truncation at a chunked stall cannot by itself prove that all audio/video packets arrived. No measured arrival timing, browser/player buffer, physical iPhone/Samsung/desktop acceptance, or safe legacy fallback decision. Keep production raw replay unchanged, not silently enabled by this prototype.

## Previous offline prototype


Requires Python 3, PyAV (`python3-av`), and FFmpeg. On this Pi, Python 3.13 / PyAV 14.2.0 and FFmpeg 7.1.5 were available. The current Docker runtime installs FFmpeg but **not Python/PyAV**; no sidecar package or deployment was added.

```sh
python3 -m unittest discover -s prototypes/live_packet_continuity -v
python3 prototypes/live_packet_continuity/stitch.py \
  --hls --output /home/christopherklint/.hermes/cache/scratch/live-eof-samples/local-continuity-hls \
  /home/christopherklint/.hermes/cache/scratch/live-eof-samples/first.ts \
  /home/christopherklint/.hermes/cache/scratch/live-eof-samples/second.ts
```

Use a **new, absent** output path. `--hls` streams a single PyAV TS mux into one persistent FFmpeg HLS stream-copy worker (2 s requested segments, 12-entry sliding playlist, `delete_segments+temp_file+independent_segments`). No `EXT-X-DISCONTINUITY` is introduced; segments start at keyframes, while unique non-IDR media inside a segment stays in the existing decoder chain. Omit `--hls` and use a `.ts` output for a full finite inventory. Inputs are only local files; they are never fetched from a provider. The standalone HLS artifact is **not** the authenticated `/api/live/:id/index.m3u8` plus signed `/segment/:id.ts` HTTP contract and is not hooked into the application.

The matcher retains a bounded rolling digest/PTS/DTS/keyframe history (2,048 packets per track), withholds one terminal video packet, and requires an unambiguous ordered, dual-track matched run of at least eight packets each at one uniform 90-kHz timestamp shift. It consumes the complete overlap through both committed tails before exposing any replacement media. The withheld terminal picture is emitted only after an exact or byte-prefix replacement at the same normalized PTS/DTS and keyframe state. Everything after the overlap gets the same timestamp shift, including non-IDR pictures and AAC. A missed duplicate, shifted audio, absent match, ambiguous static sequence, incompatible replacement, missing timestamps, codec mismatch, or DTS regression/gap aborts the presentation; it **never appends an unverified raw new session**. On failure the standalone HLS directory is cleared and replaced with an `UNSAFE` marker, not a playlist.

Limits: 2–8 TS files, 64 MiB/file and 192 MiB total input, at most 4,096 packets/32 MiB/30 s of wall time for overlap probing, one bounded history ring per track, one video-packet publishing lag. The probe timer cannot interrupt a blocked upstream `next()` call; this implementation only accepts finite local files. Rolling HLS has a bounded segment **count**, not a hard realtime bytes/disk ceiling. The inputs and worker are deliberately finite; continuous production ingest, stall detection, capacity admission, cancellation, HTTP ticketing, and retirement are **not implemented**.

## Unmet integration/acceptance gates

- StreamVault live route still publishes replayed media from independent FFmpeg workers. Replacing that with a persistent packet-aware ingest needs an installed/runtime-compatible PyAV sidecar (or equivalent), per-channel bounded staging/segment bytes/free-disk enforcement, shared worker lifecycle, abort/retirement/shutdown, and authenticated signed segment routing. No frontend/server route was changed; no server/client regression suite was claimed for this spike.
- If the upstream replays ~14–16 s at realtime pace and viewers only have ~2–4 s playable lead, no remuxer can hide the missing-media delay. The observed separate burst sample may help **one** occasion, not a guarantee. A real arrival-time vs playable-buffer study and repeated EOFs on physical iPhone/Samsung/desktop are required before any smooth-playback claim.
- Unsupported tracks (including subtitles), codec/timestamp changes, unknown ambiguous overlap, or inability to replace a truncated terminal packet must take explicit legacy fallback / unavailable handling in a later integration, never a silent "fixed" label. This spike fails closed rather than selecting a fallback itself.

## Isolated loopback HTTP candidate

`service.py` is a **separate local demo**, not the existing StreamVault server route. It has one admitted H.264/AAC channel, one bounded HTTP source reader, one packet stitcher/PyAV TS mux, and one persistent FFmpeg HLS worker. It reopens a chunked body at EOF or a socket stall and a Content-Length body at complete EOF; a short Content-Length body fails closed. Each session has a byte cap, the source read has a timeout, the service has a session/run cap, and the rolling HLS directory (including unpublished segments) has a polled byte cap. Failure/cancellation kills the worker and clears all served media, rather than falling back to raw replay. The local `GET /api/live/demo/authorize` requires a bearer demo key; returned playlist and every segment URL have independent HMAC tickets. HTTP binds **only to loopback**, and source URLs, tickets, and credentials are not logged. Use a new empty private directory, a local test TS server, and an API key supplied via environment:

```sh
LIVE_DEMO_SOURCE_URL=http://127.0.0.1:PORT/source LIVE_DEMO_API_KEY=YOUR_LOCAL_TEST_KEY \
  /usr/bin/python3 prototypes/live_packet_continuity/service.py \
  --directory /home/christopherklint/.hermes/cache/scratch/local-live-http
```

For a self-contained capture-backed local source and authenticated HTTP assertions, run `/usr/bin/python3 -m unittest discover -s prototypes/live_packet_continuity -p test_service.py -v`; this mock source sends the private first fixture chunked, then the second with Content-Length. It asserts signed access, retained non-IDR video, strict seam decode, stall reopening, declared-length truncation rejection, disk cap, and cancellation. Never put a production provider URL into a shell command or shared output. The fixture's terminal capture is truncated: full-tail strict decode is not a passing gate.

`Dockerfile.proof` is a **disposable packaging experiment**, not a production Dockerfile; it installs Debian's Python/PyAV and FFmpeg in `python:3.13-slim`, and explicitly invokes `/usr/bin/python3` (the image's `/usr/local/bin/python3` does not see apt's `python3-av`). Build it with `docker build -f prototypes/live_packet_continuity/Dockerfile.proof -t streamvault-packet-proof:local prototypes/live_packet_continuity`; run `/usr/bin/python3 -c 'import av; print(av.__version__)'` inside the resulting image. The actual StreamVault runtime still lacks PyAV and is unchanged.

**Blockers before safe integration:** the isolated demo uses a single finite channel and self-signed tickets rather than StreamVault authentication, channel admission or URL lease renewal; its polled cap can overshoot between polls; it has no storage reserve/idle retirement or crash cleanup, persistence/restart continuity, subtitles or audio-only/legacy fallback, or per-channel quota/worker scheduler. A socket timeout can terminate PyAV's demux and treat an unterminated chunked body as EOF only after sufficient media; exact complete-packet classification at a mid-packet stall is not yet proven for arbitrary sources. The output cannot be promoted to the server's live route without solving these and testing native iPhone/Samsung/desktop playback and realtime replay arrival versus playable lead. No production raw-replay switch, server/client route, deployment, or device validation is included.
